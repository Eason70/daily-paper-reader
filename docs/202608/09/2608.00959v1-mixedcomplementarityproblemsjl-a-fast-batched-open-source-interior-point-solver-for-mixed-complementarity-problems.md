## 摘要
混合互补问题（MCP）作为非线性规划和非合作博弈的一阶最优性条件出现，并为机器人技术中普遍存在的多智能体轨迹优化问题提供了一种自然的表述形式。这类问题的主导求解器是PATH，它在机器人问题上表现强劲，但仍然是闭源的。我们提出了MixedComplementarityProblems.jl，这是一个开源的、纯Julia实现的用于参数化MCP的内点法，它：(i) 在标准基准测试上与PATH的可靠性相匹配，(ii) 原生支持对许多参数实例进行批量并行处理，无论是在CPU线程上还是在NVIDIA GPU上，以及(iii) 支持对问题参数求解结果的高效自动微分。在一个代表机器人规划问题的多智能体变道轨迹博弈中，我们的CPU多线程批量求解器在处理一批参数实例时比顺序调用PATH快约100倍。一个GPU后端，运行相同的求解器实现而不加修改，也远快于PATH处理这些批次，但在此问题上并未超越多线程CPU；只有当每个实例的KKT系统变大时，GPU才会领先，我们描述了这种机制依赖性。我们描述了该求解器的内点法公式，以及一种抽象，使得单一求解器实现能够在密集、批量稀疏和单大规模线性代数后端上不加修改地运行，并报告了在随机生成的二次规划和轨迹博弈中与PATH的基准对比。

## Abstract
Mixed complementarity problems (MCPs) arise as the first-order optimality conditions of nonlinear programs and noncooperative games, and provide a natural formulation for multi-agent trajectory optimization problems that appear throughout robotics. The dominant solver for problems of this form is PATH, which offers strong performance on robotics problems but remains closed-source. We present MixedComplementarityProblems.jl, an open-source, pure Julia implementation of an interior point method for parametric MCPs that: (i) matches PATH's reliability on standard benchmarks, (ii) natively supports batched, parallel processing of many parameter instances, either across CPU threads or on an NVIDIA GPU, and (iii) supports efficient automatic differentiation of solutions with respect to problem parameters. On a multi-agent lane-change trajectory game representative of robotics planning problems, our CPU-multithreaded batched solver clears a batch of parametric instances ~100x faster than sequential calls to PATH. A GPU backend, running the same solver implementation unmodified, also clears these batches far faster than PATH, but does not outperform the multithreaded CPU on this problem; the GPU pulls ahead only once each per-instance KKT system grows large, and we characterize this regime dependence. We describe the solver's interior point formulation, the abstraction that lets a single solver implementation run unmodified across dense, batched-sparse, and single-large linear-algebra backends, and report benchmarks against PATH on both randomly generated quadratic programs and trajectory games.

## 2. 方法论
- **核心思想**：采用内点法求解混合互补问题，通过参数化批量抽象将“求解迭代循环”与“底层线性代数后端”解耦，使同一份求解器代码可无缝运行于密集、批量稀疏、单大规模等不同后端。
- **问题建模**：
  - 将 MCP 表示为 KKT 条件形式：`G(x,λ,μ;θ)=0`，`H(x;θ) ≥ 0 ⊥ μ ≥ 0`。
  - 引入松弛变量 `w` 和同伦参数 `ρ`，构造增广系统 `Kρ`，最后一行含 `w ⊙ μ - ρ1`。
- **算法流程（Algorithm 1）**：
  1. 初始化原始/对偶/松弛变量，μ,w > 0。
  2. 外层循环：当 `∥K0∥ > ¯K` 时反复执行。
  3. 内层 Newton 迭代：组装 `Kρ`，求解正则化 Newton 方向 `δ`。
  4. 采用“fraction-to-boundary”线搜索（有闭式解）更新变量、控制 w,μ 非负。
  5. 根据内层收敛情况自适应收紧或放松参数 ρ, ε。
- **批量算法（Algorithm 2）**：
  - 将 B 个实例按列堆叠，每个实例有自己的 ρ, ε、状态（active/solved/failed）和收敛判断。
  - 只对 active 实例进行组装、分解和求解；失败或已收敛实例冻结，避免拖慢整体。
  - 线搜索按元素并行计算，无需 host-device 同步。
- **后端抽象**：仅依赖 `residual!`、`jacobian!`、`factorize!`、`ldiv!` 四个动词；CPU 端使用 KLU 稀疏 LU，GPU 端使用 cuDSS 批量稀疏求解器。
- **可微性**：利用隐函数定理，在收敛点处 `∂z/∂θ = -(∇z K0)^{-1} ∇θ K0`，复用最后一次 Newton 分解，支持前向/反向自动微分，且符号构造为可选，不额外增加开销。

## 6. 主要结论与发现
- **单实例可靠性匹敌 PATH**：轨迹博弈中 PATH 有 28/1024 失败，Algorithm 1 全部成功；随机 QP 上成功率相近（431 vs 437）。
- **单实例速度优于 PATH**：KLU 后端下中位求解在 QP 上约快 7 倍，在轨迹博弈上约快 55 倍。
- **批量加速显著**：CPU 多线程批量在轨迹博弈上比 PATH 串行约快 105.5 倍，在 QP 上快 6.8 倍。
- **线程缩放**：吞吐量随线程数增加但次线性，四线程后收益骤降，接近物理核心饱和后无进一步增益。
- **GPU 依赖机制**：GPU 仅在大且足够稠密的每实例 KKT 系统上领先（如大 nx 的 QP，最多约 3 倍）；在稀疏轨迹博弈上，CPU 始终更快，因为 CPU 可跳过非 active 实例，而 cuDSS 总是处理整个批次。
- **自动化微分可行**：与中心差分相比精度高，表明可嵌入学习管线。

## 7. 优点
- **开源且纯 Julia**：可定制、易扩展，降低依赖闭源工具的风险。
- **批量原生支持**：CPU 多线程与 GPU 统一接口，显著提升参数化/场景规划吞吐。
- **设备无关抽象**：动词化后端设计使单一求解器循环可跨后端复用，便于新增策略。
- **支持自动微分**：利用内点法平滑性，零额外分解开销实现前向/反向微分。
- **自适应失败处理**：逐实例状态管理避免个别困难/不可行实例拖垮整批。

## 8. 不足与局限
- **实验覆盖有限**：仅两类问题族（随机 QP 与单一变道轨迹博弈），无法全面代表机器人领域所有 MCP 形态。
- **长时域鲁棒性不足**：轨迹博弈在 T=30 时求解率约 92%，T=50 时降至约 57%，冷启动更差，影响结论对长时域问题的推广。
- **GPU 后端的 active-set 缺失**：cuDSS 固定处理整个批次，无法像 CPU 一样跳过已收敛实例，导致 GPU 在稀疏问题上劣势明显。
- **不可行实例的拖尾**：随机 QP 中约半数不可行，单实例串行均值被拉高；虽然批处理缓解，但该问题族本身的可解释性受限（如 nx 增大时求解率从 41% 升至 100%）。
- **微分实际成本未量化**：论文验证了微分精度，但未报告批量求解中自动微分的额外墙钟开销。
- **未部署验证**：未在真实机器人/规划器中测试实时闭环性能，实际收益仍需落地验证。

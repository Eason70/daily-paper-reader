## 摘要
利用多智能体强化学习训练基于LLM的多智能体系统正迅速受到关注，而一条并行的工作线则认为，此类系统应以其行为而非仅仅奖励来评判。我们在空间合作游戏中同时采纳这两条线索，其中使用低级动作提示的小型冻结LLM会彻底失败，获得零奖励。在选项/半马尔可夫决策过程框架的指导下——并且由于选项执行在智能体间是异步的，其在宏动作Dec-POMDP中的多智能体扩展——我们为每个游戏配备了一个符号化选项库：由符号规划器执行的带类型、状态可行且短视界的行为。每个库由前沿编码模型根据游戏源代码起草；然后通过廉价的随机策略预热回放机械地合成过滤每个菜单的可行性守卫——仅当守卫能解释重复执行失败且不隐藏任何已记录的成功时才采用该守卫——因此没有守卫是由人工编写、选择或奖励调优的。每个智能体的LLM充当其对选项的策略，通过每个智能体变体的多智能体GRPO（PA-MAGRPO）训练私有每智能体LoRA适配器；这将冻结的基础模型从零奖励提升到在三个游戏和四个小型骨干网络上胜任游戏。随后的行为审计显示奖励与合作脱钩：上升的奖励曲线可能仅意味着一个智能体已学会独自执行整个任务，而其伙伴则闲置——只有当任务使其成为必要时，合作才会出现。因此，仅靠奖励是合作不可靠的读数；行为评估必须与其并置。

## Abstract
Training LLM-based multi-agent systems with multi-agent reinforcement learning is rapidly gaining traction, and a parallel line of work argues that such systems should be judged by their behavior, not only their reward. We take up both threads in spatial cooperative games, where small frozen LLMs prompted with low-level actions fail outright, earning zero reward. Guided by the options/semi-MDP framework---and, because option execution is asynchronous across agents, its multi-agent extension in macro-action Dec-POMDPs---we equip each game with a library of symbolic \emph{options}: typed, state-feasible, short-horizon behaviors executed by a symbolic planner. Each library is drafted by a frontier coding model from the game's source code; the feasibility guards that filter each menu are then synthesized mechanically from cheap random-policy burn-in rollouts---a guard is adopted only if it explains repeated execution failures while hiding no logged success---so no guard is authored, selected, or reward-tuned by hand. Each agent's LLM acts as its policy over options, with a private per-agent LoRA adapter trained by a per-agent variant of multi-agent GRPO (PA-MAGRPO); this lifts frozen bases from zero reward to competent play across three games and four small backbones. Behavioral audits then reveal that reward and cooperation decouple: a rising reward curve may simply mean that one agent has learned to run the entire task alone while its partner idles---cooperation emerges only when the task makes it necessary. Reward alone is thus an unreliable readout of cooperation; behavioral evaluation must sit alongside it.

- **核心问题**：小型冻结LLM（2–4B）在2D空间合作游戏中直接输出低级动作会出现两个典型失败模式：
  1. **空间幻觉**：模型给出貌似合理的决策但未验证空间前提条件（如面朝错误方向却发射清洁光束）；
  2. **模式崩溃**：模型在多个合法动作中收敛到某一个“安全的”默认动作（如95.8%的决策都是FIRE_CLEAN），且单智能体RL微调只会加剧这种崩溃。
  此外还存在**长时程稀疏奖励**（决策级别过多、信用分配困难）和**角色分化**问题（共享权重平均了冲突角色梯度，导致所有智能体行为趋同）。
- **整体含义**：作者提出了一种由“符号化选项库 + 每智能体LoRA适配器 + 每智能体MAGRPO训练”组成的完整配方，使小型LLM能够胜任空间合作游戏；但更重要的是，行为审计发现**奖励与合作并不等价**：高奖励可能只是单智能体独自完成任务，而真正的合作仅当任务结构强制要求时才出现。因此仅靠奖励评估多智能体系统是不可靠的，行为指标必须与奖励并置。

## 2. 论文提出的方法论

- **核心思想：时间抽象与选项机制**
  - 将LLM的决策空间从原始动作（上/下/左/右/交互）提升到一组**符号化选项**（option），如 `move_to(x,y)`、`pick_up(onion)`、`clean(dirt)` 等。
  - 每个选项是一个命名行为，配有**类型化契约**（实例化条件、符号执行器、终止条件、效果谓词）；LLM在每个决策点从一列**状态过滤后的可行菜单**中选择一个选项，由符号规划器展开为原始动作序列。
  - 形式上，单个智能体的决策问题变成**semi-MDP**，由于各智能体选项执行异步，团队层面是**macro-action Dec-POMDP**；本文方法是其中的分散式宏策略学习，以LLM作为选项策略。

- **选项库构建的四阶段流程**：
  1. **Stage 1：草案生成（唯一的前沿模型步骤）**：让 Claude Opus 4.8 阅读游戏源代码，生成“带效果谓词”的选项模式。效果谓词采用**增量（delta）形式**（如“执行前后持有的物品从X变为Y”），避免绝对形式导致的“无操作却被记录为成功”问题。
  2. **Stage 2：均匀随机预热回放（无LLM）**：用“均匀随机选择菜单选项”的策略进行大量回放（如Overcooked上约2000+2000回合、约55万决策），记录每个选项执行是否满足效果谓词（成功/失败），全程无GPU，约70秒CPU单核。
  3. **Stage 3：守卫合成与验收证书**：在回放日志中，把出现至少5次且覆盖0次成功记录的谓词合取式采纳为可行性守卫；显式失败原因（如NoPath）也直接转为守卫。该“纯净化”标准确保守卫只反映执行合法性，而非策略偏好。
  4. **Stage 4：菜单组装**：按每个目标类实例化菜单项，用守卫过滤不可行选项，每步随机打乱菜单字母顺序，防止模型利用位置偏好。
  - 另有外层“契约修复环”：若效果谓词或实例化逻辑有缺陷，机械层会检测到异常模式，再由前沿模型修复模式，重新运行2–3阶段。

- **每智能体LoRA适配器 + PA-MAGRPO**
  - 所有智能体共享同一个冻结基座LLM，但每个智能体拥有**私有LoRA适配器**，负责在共享语言先验之上表达差异化角色。
  - **PA-MAGRPO训练流程**（算法1）：
    1. 每轮采样K条并行联合轨迹，所有智能体通过选项菜单与环境交互；
    2. 每条轨迹获得共享团队回报 Rk；
    3. 在K条轨迹内做归一化得到组相对优势 Â = (Rk − μ)/σ，所有智能体共用该优势；
    4. 每个智能体仅在自己的决策子集上执行PPO裁剪更新，并加KL惩罚约束到参考策略；
    5. 只更新各智能体自己的LoRA。这样角色差异可以从随机探索中累积而非被平均掉。

- **解决三大障碍的对应关系**：选项机制解决“低级动作空间崩溃”和“长时程信用分配”；每智能体私有LoRA解决“角色分化失败”。

## 6. 论文的主要结论与发现

- **方法有效**：完整方法在全部三个游戏、四个骨干上均从冻结基座“零奖励”提升到非平凡水平。例如Qwen3-4B上Cleanup苹果从0到92.85±13.23；Overcooked AA交付从0到6.21±0.80；Commons Harvest从0到85.41±6.63。固定骨干消融表中完整方法达到Cleanup 93.25±16.84、Overcooked AA 6.80±1.89、Harvest 95.68±15.63。
- **两个成分缺一不可**：
  - 去掉选项菜单（Ablation A）在所有游戏上全部为0且从未出现正回报检查点；
  - 单一共享LoRA（Ablation B）训练不稳定，Cleanup仅0.10±0.45，角色无法同时表达；说明每智能体私有容量对于角色分化是关键。
- **行为审计揭示奖励与合作脱钩**：
  - **Cleanup**：虽然没有角色标签，7个智能体自发分化为“食苹果者”（约57–60个苹果）和“清洁者”（0苹果），空间热图显示两者分工明确；
  - **Overcooked AA**：高交付量来自“一工作/一闲置”结构——智能体0约69%时间装载洋葱，智能体1约72%时间等待，双方计数器操作均为0，即没有协作交接；同样布局下单独运行每个智能体都能独立交付，说明AA是“可单解”任务，奖励高估了合作。而Forced Coordination中训练模型达到7.57±1.16次交付，且单独运行交付为0，证明合作只在任务强制时出现；
  - **Commons Harvest**：奖励提升有限（冻结76.73±16.29 vs 训练98.29±14.52），但冻结基座到约200步耗光所有6个斑块，训练模型到400步仍保持约2.5个斑块存活。几乎平坦的奖励曲线背后隐藏着真实的资源节制行为。
- **总体结论**：同一固定配方下，奖励曲线与真实合作行为之间不存在可靠对应关系；团队奖励不能代替行为评估。

- **基线选择稍显不对称**：冻结模型已经是某种“弱基线”；没有与经典的MARL算法（如MAPPO、VDN、QMIX）在相同游戏上进行比较，因此无法判断这些模块化选项+LLM策略相比传统符号策略方法在样本效率或行为质量上的相对优劣。

## 9. 对AI与多智能体研究的启示

- **用“选项”弥合语言模型与具身空间之间的鸿沟是可行的**：将LLM定位为“高层意向选择器”，而把空间连续动作交给符号执行器，既发挥了语言先验的长处，又回避了空间推理的短板。这暗示未来的LLM具身系统或许不必强行提升模型的空间推理能力，而是通过更好的动作抽象来绕开该短板。
- **“行为审计”应当成为多智能体系统评估的标准动作**：本文最深刻的教训是——仅凭奖励或回报指标报告“成功”会掩盖真实的合作和策略结构语义。未来的LLM多智能体论文在报告团队得分之外，还应至少报告：个体行为分布、空间/状态覆盖、是否需要伙伴、以及“默认动作比率”这类反模式指标。
- **共享权重与角色分化之间的矛盾**：当多智能体共享骨干时，即使初始位置和任务优先不同，在共享梯度下它们也倾向于坍缩为同一行为，而每智能体独立适配器提供了一条低成本、比例化的角色分化路径。这提示未来的多智能体LLM框架应当默认采用“共享基础 + 独立轻量适配器”的架构。
- **“强制协调”与“可选协调”的任务结构差异是理解合作涌现的关键维度**：作者通过AA/FC对照证明，自利训练并不会自动产生合作，合作的涌现几乎完全取决于奖励结构是否排除独立完成路径。因此评估合作能力时，区分“任务结构允许单干”与“任务结构要求合作”是必须的分析维度。
- **稀疏奖励下的行为涌现值得细分**：Commons Harvest案例展示了一个反直觉结果——训练只带来微小的奖励提升，却带来了本质性的资源管理行为改变（从耗尽所有斑块到保留一半存活）。这说明在稀疏奖励多智能体任务中，平坦的奖励曲线不一定等于没有学习，行为级检查才是判断训练效果的金标准。

## 10. 总评语

该论文的核心贡献并非简单地“让LLM玩好一个游戏”，而是提供了一个端到端可复现的配方（符号选项库 + 每智能体LoRA + MAGRPO）来解决空间多智能体LLM策略的三大障碍，并以此为工具，深入地揭示了奖励信号与真实合作行为之间存在的系统性脱节。其方法设计具有工程上的优雅性（守卫合成机制避免手工规则凋零、增量效果谓词解决虚假成功），其结论具有方法论上的警示意义（不能以团队回报作为多智能体的唯一评价标准）。诚然，统计上的全种子消融缺失、对单一前沿模型代码生成的一次性依赖，及与经典MARL算法的对比空白，使该工作仍有改进空间。但就“如何训练小型LLM做空间多智能体策略”这个问题而言，本文给出了目前最完整、最自洽的答案之一，并为后续研究提供了清晰的方向标与反模式清单。
